# 图形选型验收

这组场景检查默认选型，不替代 C01–C10 的编排、故障与恢复验收。
请求只提供目标与事实，不指定 SVG、流程图、网页布局或 View 数量
（D07 明确两个部分需要独立维护）。此评分标准不写入测试 Space，
不注入 Main/View 的请求，禁止把预期实现伪装成模型的自主选择。

| 场景 | 选型预期 | 必须保真的语义与实际交互 |
| --- | --- | --- |
| D01 订单履约 | 有分支的流程 | 库存/扣款失败去向正确；选中步骤展示前提 |
| D02 支付回调 | 参与者时序或泳道 | 验签先于记账；重复不记账；切换三条路径 |
| D03 发布依赖 | 依赖图 | 两路并行、两项汇合；前置未完成不能提前完成任务 |
| D04 工单状态 | 状态转换 | 等待返回处理中、解决后可重开、关闭不可逆；动作推进状态 |
| D05 故障方案对照 | 同尺度对照流程 | 不捏造数值；故障时 A 需重提、B 保留待重试任务 |
| D06 一周转化 | 有单位和轴的图表 | 访问/下单/计算后的转化率可切换，选日期显示精确值 |
| D07 推荐闭环 | 主图关系 + 两个真实内嵌成果 | 过程与观测分工；局部选择联动；区分相关性与因果 |
| D08 团队职责 | 职责与数据关系 | 归属与传递用不同编码，有可读图例；双向选中查看关系 |
| D09 实际录入 | 表单与记录列表 | 必填校验、添加、编辑、删除；不强塞图，不宣称保存成功到服务端 |
| D10 简短回答 | 一句话文本 | 不新建 View，不生成冗余主页面 |

每例记录三层证据，分别标记结果：

1. **真实执行**：实际 thread/turn、Main 计划、View 结果、整合、错误/审批/耗时。
2. **产物检查**：Main 分派形式与理由；实际实体、边、轴与数据；全量内嵌。
   `<svg>` 数量只是观察信号，图标不算图，不据此自动判为通过。
3. **浏览器检查**：嵌入可读性、标签/连线、主交互真实变化，以及表单和问答对照。
   未操作的项目明确标为未验证，不把生成成功当作交互成功。

通过 `python3 prototype/tests/live_agent_cases/run.py D01 --suite visual --label visual-v1`
运行单例，结果和证据存入 `live-agent-cases/D01-订单履约/` 并出现在 Space 列表。
现有 Space 不自动清空，重复运行会作为后续请求保留历史。调试后的效果需和首轮分开记录。
